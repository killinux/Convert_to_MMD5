# 表情设计:多种来源 × 两种输出(MMD 表情 / Faceit)

面板第 3 页「表情」,代码在 `expression/`。用法见 [使用说明](使用说明.md) 第 4 节、[操作手册](操作手册.md) §6.7;
「脸骨」来源本身怎么算见 [face_morphs_design.md](face_morphs_design.md)。

除「脸骨」「FF7 脸骨」来源、「自动」选来源和「手调」外,引擎、配方、DNA 求值、UE5 完整权重恢复、Faceit 注册
都移植自 ripper_tpose 的 expression_kit 插件(2026-09-27 版),对象上的标记格式相同,两个插件互认对方做的表情。

```

                restore_weights / stash / restore / export_pmx / capture
  engine.py     来源 + 配方 → 骨骼 morph / 形态键;一个名字只留一种;自动方式;旧标记认领
  sources.py    来源:脸骨、FF7 脸骨、DNA、已有形态键、姿势库、骨骼脸,以及「自动」
  ff7.py        FF7 Remake / Rebirth 脸骨:表情数据 JSON → 骨骼姿势;FF7 的 MMD / ARKit 配方

  names.py      ARKit 52 名单、各种写法的识别、PMX 表情面板分类
```

## 1. 来源 × 输出

| 来源 | 什么模型 | MMD 骨骼 | MMD 顶点 | ARKit 52 |
|---|---|---|---|---|
| **脸骨**(FACEBONES) | UE MetaHuman 式脸骨 `FACIAL_*`,没有 DNA | 可以 | 可以(烘焙) | 不行(没有 ARKit 配方) |
| **FF7 脸骨**(FF7) | FF7 Remake / Rebirth 的 `C_FaceBase_a` 脸骨 + 表情数据 JSON | 可以 | 可以 | 52 个 |
| **DNA** | 有 `FACIAL_*` 且有这张脸的 `.dna` | 可以 | 可以 | 52 个 |
| **已有形态键**(SHAPES) | 模型自带 ARKit 形态键,写法不限 | 不行(没有骨骼动作) | 可以(按配方混合) | 已经有了,直接注册 |
| **姿势库**(POSES) | 任何骨骼脸:自己记录的姿势 / 带姿势标记的动作 | 可以 | 可以 | 可以(名字用 ARKit 名) |
| **骨骼脸**(ROLES) | 只有眼皮、眉、下巴、嘴唇、舌头骨(Rise of Eros 式) | 可以 | 可以 | 48 个(实验性) |

**自动**(`sources.auto_kind`):给了 DNA 文件 → 模型**自带**的 ARKit 形态键 ≥ 20 个 → FF7 脸骨(`C_FaceBase_a` +
眼球 + 眼皮骨,且找到表情数据;找不到就提示选文件)→ MetaHuman 脸骨(`FACIAL_C_FacialRoot` + 四根 `Eyelid*A`)
→ 骨骼脸(标定成功,且认出眼皮、下巴或嘴角之一——只有眼球骨的普通模型不算)。姿势库从不猜。

- 「自带」的意思:本工具烘焙出来的 ARKit 形态键带标记,不计入。否则第一次生成 ARKit 之后,再点一次
  「自动」就会改用「已有形态键」,把我们自己的烘焙结果再混一遍(ROE 测试里踩到,已修)。
- 选「已有形态键」做 MMD 表情时,方式自动改成顶点(这种来源没有骨骼动作),报告里注明,不报错。

两种输出在一次「生成表情」里各自走一遍 `api.build`:MMD 用面板上的方式 / 类别 / 强度,ARKit 总是形态键。
勾了「生成后注册到 Faceit」且确实有 ARKit 形态键(或来源是「已有形态键」)时接着注册;Faceit 没装或没启用
时报一行提示,不算失败。

注册还要管角色朝向:Faceit 把手机传来的头部转动换成世界坐标里的旋转时,默认角色朝 -Y。朝 +X 的模型(UE 导出)
左右转头正常,俯仰和侧倾却对调。`faceit.face_front` 用 eyeBlinkLeft / eyeBlinkRight 移动的位置(按位移加权的
中心)求角色的左方,前方 = 左 × 上;不朝 -Y(差 10° 以上,接近坐标轴的取整到 90°)就把骨架和网格的顶层物体
绕骨架原点、Z 轴转过来。只改物体变换;只转骨架不够,没挂在骨架下的网格不会跟着转。

## 2. MMD 表情和 Faceit 能不能一起用

能。一个 `.blend` 里可以同时有 MMD 表情和 52 个 ARKit 形态键,名字不一样。会冲突的地方:

| 冲突 | 后果 | 处理 |
|---|---|---|
| 同一个 MMD 名字既有骨骼 morph 又有顶点 morph | MMD 两个都执行,脸动两次 | 写一种时删掉同名的另一种(见 §5) |
| mmd_tools 导出 PMX 把**所有**形态键写成顶点 morph | 52 个 ARKit 键进 PMX 当「其他」表情(Fiona 15.9 → 20.7 MB) | 「导出 PMX」默认把 ARKit 键暂时拿开;勾「带 ARKit 形态键」才写,且排在 MMD 表情后面 |
| 一键转换的步 4「修正前腕弯曲」跳过带形态键的网格 | 带着形态键转换,手臂会歪 | 转换前「暂存」(形态键存进一个隐藏副本),转换后「恢复」(模型被转向或缩放成米也跟着换算) |
| PMX 每个顶点只存 4 个骨骼权重,MetaHuman 脸最多 12 个 | 骨骼 morph 在 MMD 里鼓包 | 「骨骼表情误差预估」先算;「自动」按阈值逐个选;顶点 morph 没有这个问题 |
| UE Viewer 导出时就把权重截成了 4 个 | 在 Blender 里烘焙的表情也鼓包 | 「恢复完整权重」(要游戏包 `.uasset.bin`);分析时提示 |
| Faceit 只驱动 ARKit 形态键 | 面捕时 MMD 骨骼 morph 不参与 | 各管各的:Faceit 用 ARKit 键,MMD 用 PMX 里的表情 |

## 3. 原理

### 3.1 脸骨(MetaHuman,无 DNA)

`convert/face.py` 的位置驱动「场」:每个表情由眼皮、下巴、嘴角、唇、眉、脸颊、舌、牙几个场叠加,按骨头位置
算出每根骨的骨架空间变换,再换成相对父骨的局部偏移。眼皮闭合角按皮肤网格上实测的眼睑边缘逐骨标定。
详见 [face_morphs_design.md](face_morphs_design.md)。接进引擎后(`sources.FaceBoneSource`):

- 配方就是 `face.MORPHS`(按名字对上 recipes 的 MMD 名单,59 个;瞳小 没有);
- 强度 ≠ 1 时按 MMD 的 morph 权重语义缩放:平移乘系数,旋转按角度乘系数;
- 只能做 MMD 表情。ARKit 52 需要的眼球转向、单侧唇、鼻翼等这里没有对应的场,要做得另写一套配方。

### 3.1b FF7 脸骨(Remake / Rebirth)

FF7 Remake / Rebirth 的脸是 `C_FaceBase_a` 下 103 根平级的脸骨(上眼皮 Ulid A–E、下眼皮 Dlid A–C、睫毛、褶、眼袋、
眉、额、眉间、颧、脸颊、鼻、法令纹、内外唇、嘴角、下巴、牙、舌根舌尖、喉),网格没有形态键。游戏里表情分三层
(Rebirth 的调研见 ripper_tpose `docs/ff7rebirth-face.md`):

- **表情姿势**:`Facial00/F_*` 单帧姿势(`F_Idle01` = 平静脸),放在动画蓝图的「FacialSlot」槽里播,由三个
  BlendSpace 混合——情绪二维网格(悲伤 / 厌恶 / 愤怒 / 疲倦 / 平静 / 惊讶 / 冷笑 / 微笑 / 开心 / 严肃)、眉、
  眼皮跟随视线(往上看 13° 用 `F_Eyelid_up01`、往下 20° 用 `down01`、左右 22° 用 `left01` / `right01`);
- **口型**:`HSFLipMap` 的 7 个口型(aa ee oo sh fv ln bmp)是每根嘴部骨骼的通道值,由每句台词的
  `HSFLipSyncDataPack`(时间轴、音素、口型权重、音量)驱动;
- **过场**:逐镜头的脸部骨骼动画(日语 / 英语各一套)。

**表情数据 JSON**(游戏数据,不进仓库)由 ripper_tpose 的脚本生成:Remake 用 `scripts/final/ff7_face_data.py`
(UE Viewer 导出姿势 + 解析口型表);Rebirth 用 `scripts/final/ff7rb_face_data.py`(CUE4Parse 导出口型表、视线
BlendSpace 和骨架;姿势动画 CUE4Parse 解不了,脚本自己从原始包里读 ACL 1.3 压缩数据——单帧姿势的轨道全是常量,
不用解变码率部分。Tifa 24 个姿势里 23 个这样解出,和 Remake 的逐骨差 ≤ 0.4 mm,做出的 83 个形态键差 ≤ 0.09 mm;
带动态轨道的 F_Angry02 用 `--poses-from` 从 Remake 补)。内容:24 个姿势(脸坐标系里相对绑定姿势的 4×4:原点
`C_FaceBase_a`、X 前 / Y 左 / Z 上、厘米)、口型表、视线角度。插件按两眼间距缩放到模型上,所以米尺度的模型也能用。放在 `.blend` 上层的
`_meta/face` 文件夹里(导出目录的布局 `<游戏>/<角色>/blend/<模型>/<模型>.blend` → `<游戏>/_meta/face`)会按
角色编号(`PC0002`)自动找到,也可以在面板里选,或设环境变量 `FF7_FACE_DATA_DIR`。

**配方**(`ff7.py`)是一串分量,权重相乘(平移按比例、旋转按角度):

| 分量 | 含义 |
|---|---|
| `("pose", F_*, 区域, 权重, 侧)` | 游戏姿势相对 `F_Idle01`,只取这些区域的骨 |
| `("lip", 口型, 区域, 权重, 侧)` | 口型相对它的静止值 |
| `("move", 区域, (前, 左, 上), 侧)` | 按骨骼算的平移,单位 = 两眼间距 |
| `("gaze", 眼皮姿势, 侧, 倍数)` | 眼球转到这个眼皮姿势对应的视线角度 |

区域:上 / 下眼皮、眼球、眉、颧、下脸颊、鼻、法令纹、上 / 下嘴角、上 / 下唇、下巴(含下牙、喉、下颌角)、上牙、舌。
「侧」为 L / R 时只取这一侧的骨,中线骨(C_)按一半。

- **MMD**:移植 ff7_face_morphs 的 29 个(+ 2 个别名):眼、眉取对应姿势的眼皮 / 眉区域,あいうえお 用游戏口型。
- **ARKit 52**:
  - 眨眼 = `F_Eyelid_blink01` 的一侧眼皮;
  - eyeLook = 视线跟随姿势的一侧眼皮 + 眼球按 BlendSpace 的角度转(往外看左眼用 `left01`,往内用 `right01`,
    右眼相反;`left01` 的眼皮整体往角色左边偏,确认了 +22° = 往角色左边看);
  - 眯眼 / 睁大 / 颧上提 = Glad01 的下眼皮、Surprise01 的眼皮、Glad01 的颧;
  - 眉:下压 = `F_Brow_down01`,内侧上扬 = `F_Sad01` 的眉,外侧上扬 = `F_Brow_up_left01` / `right01`
    (它抬的是角色自己那一侧);
  - 嘴:单侧笑 = Smile01 的嘴一侧,上唇上提 / 皱鼻 = Disgust01 的上唇 / 鼻颧,嘟嘴 / 噘嘴 = 口型 oo(+ bmp 合唇),
    下唇下拉 = ee 的下唇,抿嘴 = bmp,卷下唇 = fv 的下唇;
  - 张嘴 = 口型 aa 的下巴 + 下唇 + 舌 ×1.4(aa 只有满张嘴的七成);mouthClose = 「aa 只动下巴」减去 jawOpen,
    即下唇不跟下巴走——单独看会往上顶,跟 jawOpen 叠加才是合唇张嘴(ARKit 的规定);
  - 没有对应姿势的(嘴角下撇——Disgust01 其实把嘴角往上提、Sad01 几乎不动;嘴角外拉、酒窝、嘴 / 下巴左右移、
    下巴前伸、卷上唇、耸唇、鼓腮、伸舌)按骨骼平移;
  - 游戏的姿势偏含蓄,而面捕给 1.0 的是极限,所以单侧笑、眯眼、睁大、颧、皱鼻、抿嘴等权重 1.3–2(逐个渲染定的)。
- 每个都只是初稿,不满意的用「手调」改(§3.10)。

### 3.2 MetaHuman DNA

MetaHuman 的脸没有表情形态键,UE 运行时由 RigLogic 按 DNA 把约 270 个原始控制量换算成约 600 根 `FACIAL_*`
关节的动作。

1. DNA 关节和模型骨骼配对:同名 → 忽略大小写 → 转换加的 `unused_` 前缀 → XPS / MMD 改的名字(眼球、下巴)→
   还没配上的,看相似变换拟合后的位置,1 mm 内有一根面部骨就配它。Fiona(本插件转换后):620/620,平均 0.38 mm。
2. 每个表情是一组原始控制量(配方),**整组一起**送进 RigLogic:PSD 组合修正(例如同时张嘴和笑)自然算进去。
3. 每根关节的世界增量施加到对应骨骼的静止矩阵上,换算成 `matrix_basis`(与 Blender 骨骼轴向无关)。
4. ARKit 的 mouthClose 是「张着下巴时把嘴唇合上」:量的是 (jawOpen + 合唇) − jawOpen。
5. DNA 的缩放输出也算进去了:Fiona 只有两根瞳孔关节会缩放,`瞳小` = `eyePupilNarrow` 0.6。PMX 骨骼 morph
   不能缩放,所以 `瞳小` 只能做成顶点 morph(骨骼方式跳过并说明,「自动」直接选顶点)。

### 3.3 已有形态键

每个网格按配方加权求和:Σ 权重 ×(形态键 − 它的参考键)。ARKit 名字的各种写法都认(`eyeBlink_L`、
`EyeBlinkLeft`、`Eye_Blink_L` ……)。配方里以 `?` 开头的是可选键(星刃的 `TeethLowerDown` 要跟着张嘴)。

### 3.4 姿势库

- **记录**:摆好脸部骨骼,起名(MMD 名或 ARKit 名)→「记录当前姿势」,存在骨架对象的 `expression_kit_poses`
  属性里(JSON),随 `.blend` 保存。
- **动作**:有姿势标记时每个标记是一个姿势;没有时整个动作的第一帧算一个(用动作名)。直接读 F 曲线。
- **中性姿势**:游戏的「无表情」不一定是绑定姿势,填了就其余姿势都减掉它。
- 混合和 MMD 叠加骨骼 morph 一样:位移相加,旋转按权重缩放后相乘。

### 3.5 骨骼脸

按「角色」找骨(upper_lid_L、chin、corner_R ……,三种拼写都认;`AC` 辅助骨跳过,挂在别处的算跟随骨)。
每个表情写成几条 `(角色, pitch/roll/yaw/move, 量)`,距离以两眼间距为单位,正方向是转 1° 实测出来的。

### 3.6 姿势 → 形态键(烘焙)

整副骨架回到静止:约束静音、骨架以外的修改器关掉、已有形态键归零。逐个表情摆姿势,求值网格,减去静止时的
位置存成形态键,结束后全部恢复。用的是网格上的**全部**权重,所以形态键就是骨骼脸真实做出来的样子。
相连的骨骼在 Blender 里不能平移,要平移的先断开连接(PMX 没有这个概念,导出不受影响)。

### 3.7 PMX 误差和「自动」

mmd_tools 导出时,超过 4 个的权重只留最大的 4 个再归一化。对这些顶点在同一姿势下做两次线性蒙皮(全部权重 /
前 4 个),两者差得最大的值就是这个表情做成骨骼 morph 时在 MMD 里的偏差。「自动」逐个比较:不超过阈值
(默认 0.3 mm)做骨骼 morph,否则做顶点 morph。误差只要姿势、不用求值网格,所以先算误差、要做顶点的才烘焙。
XPS 路线的脸只剩 4 个权重(Fiona 只有 536 个顶点有 5~6 个),误差基本为 0,全部是骨骼 morph。

### 3.8 恢复完整权重(UE5)

UE Viewer 每个顶点只导出 4 个权重。直接从游戏包的字节里读出完整权重(UE5 zen 包,按特征查找,不需要 usmap),
按顶点位置写回;只改写「当前权重正好是游戏权重截断后重新归一化」的顶点,手工改过的不动。能用在转换后的模型
上:XPS 拆开的网格(眼球、牙、睫毛)按各自的顶点检查;改过名的骨(`head` → `頭`、`FACIAL_C_Jaw` → `head jaw`)
按权重重叠找回。

### 3.9 写进 mmd_tools

- **骨骼 morph**:`root.mmd_root.bone_morphs`,每项存骨名、位移、四元数(姿势空间)。被平移的骨解开位置锁
  (mmd_tools 把位置全锁的骨导出成「不可移动」)。
- **顶点 morph**:形态键本身,再登记到 `vertex_morphs`(英文名、面板分类、顺序)。没登记的形态键在 PMX 里会
  排在最前面,所以 ARKit 键登记在 MMD 表情后面,归「其他」。
- 改完重建「表情」显示枠(MMD 的表情面板读它);改动前解绑 morph slider,改完重建。

### 3.10 手调(逐个表情手动修改)

任何会动骨骼的来源(脸骨、FF7 脸骨、DNA、骨骼脸)都能手调:

1. 选表情组(ARKit / MMD)和表情 →「载入到骨架」:有手调用手调,没有用来源算的初稿,摆到脸骨上;
2. 在姿势模式里改脸骨;
3. 「保存手调」:骨架上脸骨的当前姿势存成姿势库条目,名字就是表情名(骨架对象的 `expression_kit_poses`,随
   `.blend` 保存,姿势库来源读的也是它);
4. 「生成表情」时,勾着「手调优先」的话,有同名手调的表情用手调姿势,其余用来源(`manual.ManualOverride` 包一层)。

- **镜像到另一侧**:骨架上的当前姿势左右镜像,存成对侧的表情(eyeBlinkLeft ↔ eyeBlinkRight、ウィンク ↔ ウィンク右、
  困る左 ↔ 困る右),并摆到骨架上。镜像面过两眼中点、法向是两眼连线(没有眼球骨就用 X = 0 平面);每根骨的骨架空间
  变化 S·D·S 给它的对侧骨(L_ ↔ R_、FACIAL_L_ ↔ FACIAL_R_、.L ↔ .R、左 ↔ 右……),中线骨镜像到自己;
  按父子关系换回姿势空间,有层级的脸骨(MetaHuman)也对。
- 手调过的 mouthClose 仍减去来源的 jawOpen(保持 ARKit 的含义),所以手调时摆的是「张嘴 + 合唇」。
- 「删除手调」回到初稿;「复位」把脸骨放回静止;◀ ▶ 换上一个 / 下一个表情并载入。

## 4. 标记

- 网格:`expression_kit` = JSON `{"MMD": [...], "ARKIT": [...]}`(本工具做的形态键);
  根对象:`expression_kit` = JSON `{"BONE": [...]}`(本工具做的骨骼 morph)。「清除」只删这些。
- 旧版「用脸骨做 MMD 标准表情」按钮记在根对象的 `c2m_face`(名字列表)。读取时当作本工具做的;
  第一次生成或清除 MMD 表情时并入 `expression_kit` 并删掉旧属性。

## 5. 同名与替换

- 一个名字只留一种:写骨骼 morph 前删同名形态键,写形态键前删同名骨骼 morph。
- 「替换同名」**关**(默认,沿用旧版「模型自带的同名表情不覆盖」):生成前先把模型自带 / 别人做的同名表情
  (形态键、骨骼 / 材质 / UV / 组 morph)挑出来跳过,所以真正写的时候遇到的同名表情都是本工具做的,可以直接删。
  expression_kit 原版在替换关着时连自己做的另一种也不删,骨骼 ↔ 顶点切换会留下同名的两种,这里修掉了。
- 「替换同名」**开**:别人做的同名形态键 / 骨骼 morph 也重做;同名的材质 / UV / 组 morph 不动。
- 换来源重做时,新来源没有配方的名字保留上一次的结果(例:DNA 没有 ω、歯無し,保留脸骨做的)。

## 7. 限制与后续

- **脸骨来源做不了 ARKit**:需要眼球转向、单侧唇、鼻翼、鼓腮等新场和 52 个配方。有 DNA 的 MetaHuman 脸用 DNA。
  (没有配方的表情也可以在「手调」里自己摆出来保存,生成时就有了。)
- **FF7 Rebirth 只解得出常量轨道的姿势**:标准表情姿势都是(各角色 23~25 个,含 Remake 里没有的 Cid、Vincent),
  少数带动态轨道的(Tifa 的 F_Angry02、Cloud 的待机 / 必杀表情)要用 `--poses-from` 从 Remake 补,或者不用。
  过场的逐帧脸部动画也是动态轨道,还解不了。
- **FF7 的 ARKit 是配方近似**:游戏没有逐块肌肉的形状,嘴角下撇、酒窝、鼓腮、伸舌等是按骨骼平移的。
- **DNA 只认 v2.1**(Vindictus 的版本)。MetaHuman 5.6 以后是 v2.2+ 分段格式,要新写读取。
- **骨骼脸 → ARKit 是实验性的**:没有脸颊、鼻翼骨的脸做不出 cheekPuff、noseSneer,mouthClose 也没有配方。
- **顶点 morph 在中间值走直线**:半程时下巴、眼皮走弦不走弧(下巴转 18°、半径 10 cm 时中点约差 1.2 mm)。
  「组合表情」(大骨骼用骨骼 morph,其余用顶点 morph 补差)可以兼顾,还没做。
- 照れ(脸红)、星目等材质 / UV 表情不做。
