# XPS → MMD 转换操作手册

从一个 `.xps` / `.mesh.ascii` 模型开始,到导出可用的 `.pmx`,一步一步照做即可。
面板位置:3D 视图右侧 N 面板 → **Convert to MMD** 标签页。

> 深入原理与坑位分别见 `docs/skirt_physics_design.md`、`docs/踩坑记录.md`;
> 整套流程的脚本化版本见 `test/alana_minimal_flow.py`(最小干预)与 `test/vmd_compare_test.py`(标准+对比验证)。

---

## 0. 前置准备(一次性)

1. Blender 3.6.x,启用三个插件:
   - **mmd_tools**(导入/导出 PMX 的底座)
   - **XNALaraMesh**(XPS 导入器)
   - **Convert_to_MMD5**(本插件)
2. 同类旧插件(如 Convert_to_MMD / MMD4)必须**禁用**——两者共用 bl_idname,同时启用会互相覆盖。
3. 打开面板,确认顶部 **build 时间戳** 是新的(改过代码后没变 = Blender 还在跑旧缓存,重新启用插件)。

---

## 1. 导入 XPS

`文件 → 导入 → XNALara/XPS Model`,选 `.xps` 文件。

- 导入后场景里是 1 个骨架(约 200+ 根 XPS 命名的骨) + 若干网格。
- **选中骨架对象**(后面所有按钮都要求活动对象是骨架)。

## 2. 识别骨架(填槽位)

两种方式,任选:

| 方式 | 操作 | 适用 |
|---|---|---|
| 自动 | 点 **「自动识别骨架(填充下方槽位)」** | 大多数 XPS 模型 |
| 预设 | 先点 **✕**(清空槽位)→ 下拉框选 `xna_lara` → 点 **「导入预设」** | 标准 XNALara 命名的模型 |

然后**肉眼核对**面板里的槽位:上半身/首/頭/肩/腕/ひじ/手首/下半身/足/ひざ/足首 + 手指。
识别错一根(常见:外套/轮子等杂骨把腿认成手臂),后面全错——这一步值得花 30 秒检查。

## 3. (可选)T-Pose 转 A-Pose

看源模型手臂:**水平伸直(T-Pose)才需要这步;已是斜向下(A-Pose)直接跳过。**

- 点 **「0.5 转换为 A-Pose(源为T时可选)」**。
- 效果:上臂绕全局 Y 倒下(目标 ~36°,实际落 ~50° 左右)+ 拉直肘,网格同步烘焙,形态键自动退避复原。
- 不要求和某个目标 PMX 完全对齐,A-Pose 只是 MMD 模型规范。

## 4. 转换本体(二选一)

**先选路线**:面板顶部有「**标准·重建权重** / **精简·保源权重**」双钮开关,
一键按钮和手动分步区都跟随它:

- **标准**:完整流程,转移 unused 权重并重建捩骨/掌骨(源蒙皮一般的模型);
- **精简**:源权重一律不动,权重四步(3/6/11/12)自动停用变灰
  (helper 骨真实承重、具名饰骨密集的模型,如 lezisell 系;判断准则见下文小节)。

### 路线 A:一键(推荐首选)

点 **「一键转换 XPS→MMD(标准)」**(精简路线下按钮显示为「一键转换(精简·保源权重)」,
自动跳过转移/捩骨/手掌三类权重步,日志里对应步骤记 `SKIP(精简)`)。
标准版内部自动执行:自动识别 → 归正 → 重命名 → 转移 unused 权重 →
修正前腕 → 补全缺失骨 → 二次转移 → IK → 骨骼集合 → mmd_tools 转换 → 腿D骨 → 捩骨 →
手部权重修正 → 肩P骨 → 付与设置与应用。

- 期望日志:`一键转换完成: 19/19 步成功`。有 FAIL 的步骤看控制台输出定位。
- 完成后场景里出现 mmd 结构:root 空物体(`New MMD Model`)→ 骨架 + 网格。

### 路线 B:手动分步(需要干预中间结果时)

面板「手动分步」区**从上到下按编号点**,等价于一键:

```
1 归正骨架位置 → 2 重命名为 MMD → 3 转移 unused 权重① → 4 修正前腕弯曲
→ 5 补全缺失骨骼 → 6 转移 unused 权重② → 7 添加 MMD IK → 8 创建骨骼集合
→ 9 使用 mmd_tools 转换格式        ←— 此线以上在转换前,以下在转换后
→ 10 添加腿部 D 骨 → 11 添加捩骨 → 12 手部权重修正(拇指+掌骨)
→ 13 添加肩P骨 → 14 设置标准付与 → 15 应用付与变换
```

**最小干预变体**(源权重质量好、不想动它,如 alana):面板顶部切到
**「精简·保源权重」**,分步区的 **3、6、11、12** 会自动变灰停用
(不转移 unused 权重、不切捩骨、不改手掌),其余按钮照常从上到下点。
代价是保留一批 unused 骨;好处是源蒙皮原样保留。参考 `test/alana_minimal_flow.py`。
另:步骤 4(修正前腕)只动姿态不动权重,精简路线下仍可用;若 0.5 A-Pose 已拉直肘
则它是冗余的,可跳(alana 脚本即如此)。

#### 何时跳过步 3/6(转移 unused 骨权重)

一句话原理:transfer(见 `convert/weights/transfer.py` 文件头)假设 helper 骨权重是
**待回收的原料**——把它们就近并进标准骨,好让步 11/12 在归一化的权重上重建 MMD 标准
捩骨/掌骨。这个前提不成立时(helper 权重本身就是成品蒙皮),转移只剩两种风险:
有损重蒙皮(扭转/体积梯度被压平进单一最近骨),以及分类器误判(曾把居中的具名布骨
hangings cross / shawl back middle 判成 merge,引发权重湮灭,见
`docs/skirt_physics_design.md` v3)。

| 看什么 | 倾向跳过 | 倾向跑 |
|---|---|---|
| helper 顶点组权重量级 | 总权重几百以上(真承重,如 alana pelvis 1312 顶点/foretwist 736 顶点) | 接近零(纯占位) |
| 是否跑步 11/12 重建捩骨/掌骨 | 不跑(转移没有下游消费者) | 跑(必须先转移) |
| 具名饰骨/布骨密度 | 多且命名怪(误判风险高) | 少且规整 |
| 源蒙皮质量 | 静态摆 pose 已很好 | 源本来就烂,重建损失小 |

跳过的代价(不是免费的):① 源 twist 骨在 MMD 里**无驱动**(VMD 不认、也没配付与,
只跟父骨走),手腕大幅扭转时前臂扭转不沿臂分布——裸臂大动作的模型要重新权衡;
② 残留 unused 骨对 PMXEditor 二次编辑不友好。

权重量级抽查:Blender 里统计可疑顶点组的总权重(或直接跑
`test/alana_minimal_flow.py` 的 verify 段,它会打印 foretwist/pelvis 等组的
顶点数与总权重)。

## 5. (可选)衣服权重转移

贴身衣物(泳衣/紧身衣类)蒙皮很差时用。切到面板第二个 tab:

1. 先选中衣服网格(可多选),**最后加选身体网格**(让身体是活动对象);
2. 点 **「衣服权重转移(身体→衣服)」**。

## 6. (可选)布/发物理 + 身体碰撞刚体

模型带裙/外套/披风/纱巾/飘带/物理头发时做这步。仍在第二个 tab,**顺序固定**:

1. 点 **「1. 身体碰撞刚体(自动)」** —— 给 頭/首/上半身系/下半身/腿/腕 建 kinematic 胶囊,
   半径按网格顶点实测。
2. 点 **「2. 布物理: 裙/外套/披风/发(自动)」** —— 词表识别布骨/发骨,逐骨建刚体+关节,
   锚定到就近标准骨。布关节按板面对齐朝向(MMD 稳定性关键),发链恒等朝向、±10°、零弹簧。

注意:
- **先 1 后 2**,否则布料没有身体可撞。
- 两个算子可重复运行(已有刚体的骨会跳过)。
- **建完物理后不要点 mmd_tools 的 Build 再导出**——Build 会把布骨绑上动力学刚体,
  场景一求值绑定位就被污染,导出的 PMX 关节出生即违约 → 在 MMD 里全场爆炸。
  想在 Blender 里预览物理:先导出,再在**另一个干净场景**导入该 PMX 后 Build。

## 7. 导出 PMX

1. 选中 root 空物体(`New MMD Model`)及其所有子级(大纲视图里右键 root →
   **Select Hierarchy**,或视图里选 root 后 `Shift+G → Children` 再补选 root),
   活动对象设为 root;
2. `文件 → 导出 → MikuMikuDance Model (.pmx)`,**scale = 12.5**,勾选 copy textures;
3. 导出无报错、文件几 MB 即正常。

> 转换出的模型是「米」尺度,×12.5 后即 MMD 常规身高尺度。
> 在 Blender 里给它导 VMD 测试时,VMD 的 scale 要和模型导入 scale 一致
> (如 PMX 以 0.08 导回,VMD 也用 0.08;详见 `docs/TESTING.md`)。

## 8. 验证清单

Blender 侧(能验的):

| 检查项 | 方法 | 通过标准 |
|---|---|---|
| 权重孔洞 | 脚本统计各网格顶点对骨骼组的权重和(见 alana_minimal_flow.py 的 verify 段) | 0 个顶点 < 0.05 |
| 物理结构 | 干净场景导入导出的 PMX → mmd_tools Build → 跑 60 帧静置 | 动态刚体位移 < 0.17m,无飞散 |
| 舞蹈结构 | 同上场景导 VMD 跑全曲 | 布刚体到下半身距离 < 3m(不爆炸) |

MMD 侧(必须实测的——Blender 的新版 Bullet 测不出老版 Bullet 的失稳):

1. 物理演算设为**「常に演算」**(默认"再生時のみ"会首帧跳变,看起来像爆炸);
2. 加载 PMX + 舞蹈 VMD,看:是否爆炸 / 布是否自然摆动 / 是否穿身;
3. 布的**动态手感只认 MMD 实测**,Blender 里的横飘是模拟失真,不是数据问题。

## 常见问题速查

| 症状 | 原因 → 处置 |
|---|---|
| 一键转换后手指/手臂错位 | 通过脚本/MCP 调用时 override 钉死了 active_object → 只 override window/area/region/screen(见 docs/TESTING.md §2) |
| 跳舞时某块布钉在原地拉成横板 | 权重被转移/湮灭,顶点兜底绑了全ての親 → 具名布/发骨要保留权重(transfer 已内置此规则) |
| MMD 里布料爆炸 | 关节朝向/欧拉序问题(已修,见 skirt_physics_design.md v4);仍爆则查 MMD「常に演算」设置、分叉枝端关节 |
| 转腰时腿部网格撕裂 | 足D 未继承腰キャンセル父级(已修,semistandard.py) |
| 导出的 PMX 在 MMD 里倒地/巨大 | 导出 scale 不对,用 12.5;或选错了导出根对象 |
| 面板按钮点了没反应/行为是旧版 | Blender 模块缓存 → 重新启用插件,确认面板顶部 build 时间戳已更新 |
