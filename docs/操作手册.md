# XPS → MMD 转换操作手册

从一个 `.xps` / `.mesh.ascii` 模型开始,到导出可用的 `.pmx`,一步一步照做即可。
面板位置:3D 视图右侧 N 面板 → **Convert to MMD** 标签页。
只想快速上手、查按钮作用,看更短的 [使用说明](使用说明.md)。

> 深入原理与坑位分别见 `docs/skirt_physics_design.md`、`docs/踩坑记录.md`;
> 整套流程的脚本化版本见 `test/alana_minimal_flow.py`(最小干预)与 `test/vmd_compare_test.py`(标准+对比验证)。

## 快速上手(大多数模型只要这 5 步)

1. `文件 → 导入 → XNALara/XPS Model` 导入 `.xps`,**不要缩放骨架**(保持导入尺寸,约 1.7 m 高)。
2. 选中骨架 → N 面板 **Convert to MMD** → 第一个 tab「主骨骼管理」→ 点 **「一键转换 XPS→MMD(标准)」**。
3. (可选)第二个 tab「衣服 / 刚体」:**「1. 身体碰撞刚体」**、**「2. 布物理」**、**「胸部物理(自动)」**、
   **「头发物理(自动识别发骨)」**。
4. 选中模型里任意对象(骨架即可)→ `文件 → 导出 → MikuMikuDance Model (.pmx)`,
   **Scale 改成 12.5**(mmd_tools 1.0.2 默认 1.0)、勾 **Copy textures**,存到单独的空文件夹。
5. 在 MMD 里加载 PMX + 舞蹈 VMD 实测(物理演算设「常に演算」)。

识别不对、需要手动改槽位时,见 §2 与 §4 路线 B。

---

## 0. 前置准备(一次性)

1. Blender 3.6.x,启用三个插件:
   - **mmd_tools**(导入/导出 PMX 的底座)
   - **XNALaraMesh**(XPS 导入器)
   - **Convert_to_MMD5**(本插件)
2. 同类旧插件(如 Convert_to_MMD / MMD4)必须**禁用**——两者共用 bl_idname,同时启用会互相覆盖。
3. 打开面板,确认顶部 **build 时间戳** 是新的(当前为 `build 2026-09-26 xps-names+breast+hair`;
   改过/更新过插件后没变 = Blender 还在跑旧代码,重启 Blender 或重新启用插件)。

## 1. 导入 XPS

`文件 → 导入 → XNALara/XPS Model`,选 `.xps` 文件。

- 导入后场景里是 1 个骨架(约 200+ 根 XPS 命名的骨) + 若干网格。
- **选中骨架对象**(后面所有按钮都要求活动对象是骨架)。
- **不要缩放骨架**:插件和导出(×12.5)都按导入时的「米」尺度设计。已经按 S 放大过的,
  在物体模式选中骨架按 **Alt+S** 清除缩放(网格是子级,会一起缩回)。

## 2. 识别骨架(填槽位)

两种方式,任选:

| 方式 | 操作 | 适用 |
|---|---|---|
| 自动 | 点 **「自动识别骨架(填充下方槽位)」** | 大多数 XPS 模型 |
| 预设 | 先点 **✕**(清空槽位)→ 下拉框选 `xna_lara`(选中即载入;「导入预设」是从外部 json 文件导入) | 标准 XNALara 命名的模型 |

自动识别先按拓扑认骨,再让 **XPS 标准骨名优先**:骨名是 `root hips` / `head neck upper` /
`arm left shoulder 2` / `boob left 1` 这类标准名(表即 `presets/xna_lara.json`)时直接按名字定角色,
只有孤立的同名残骨不算数。所以 blender2xps 导出的 UE 骨架(面部根骨、Bip001 Pelvis 这类会骗过
拓扑的骨)也能直接自动识别 / 一键转换。

然后**肉眼核对**面板里的槽位:上半身/首/頭/肩/腕/ひじ/手首/下半身/足/ひざ/足首 + 手指。
识别错一根(常见:外套/轮子等杂骨把腿认成手臂),后面全错——这一步值得花 30 秒检查。

> ⚠️ **「一键转换」每次都会先重新自动识别**,会覆盖你手动改过或用预设填好的槽位。
> 槽位要手动修正时,改完后走 §4 **路线 B(手动分步)**,不要点一键。

## 3. (可选)T-Pose 转 A-Pose

看源模型手臂:**水平伸直(T-Pose)才需要这步;已是斜向下(A-Pose)直接跳过。**

- 点 **「0.5 转换为 A-Pose(源为T时可选)」**。
- 效果:上臂绕全局 Y 倒下(目标 ~36°,实际落 ~50° 左右)+ 拉直肘,网格同步烘焙,形态键自动退避复原。
- 不要求和某个目标 PMX 完全对齐,A-Pose 只是 MMD 模型规范。

## 4. 转换本体(二选一)

**先选路线**:面板顶部有「**标准·重建权重** / **精简·保源权重**」双钮开关,
一键按钮和手动分步区都跟随它:

- **标准**:完整流程,转移 unused 权重并重建捩骨/掌骨(源蒙皮一般的模型);
- **精简**:源权重一律不动,权重四步(3/6/11/12)自动停用变灰
  (helper 骨真实承重、具名饰骨密集的模型,如 lezisell 系;判断准则见下文小节)。

### 路线 A:一键(推荐首选)

点 **「一键转换 XPS→MMD(标准)」**(精简路线下按钮显示为「一键转换(精简·保源权重)」,
自动跳过转移/捩骨/手掌三类权重步,日志里对应步骤记 `SKIP(精简)`)。
标准版内部自动执行:自动识别 → 归正 → 重命名 → 转移 unused 权重 →
修正前腕 → 补全缺失骨 → 二次转移 → IK → 骨骼集合 → mmd_tools 转换 → 腿D骨 → 捩骨 →
手部权重修正 → 肩P骨 → 付与设置与应用。

- 期望日志:`一键转换完成: 16/16 步成功`(精简路线另报跳过的权重步数)。有 FAIL 的步骤看
  控制台输出定位(Windows:菜单 `窗口 → 切换系统控制台`)。
- 完成后场景里出现 mmd 结构:root 空物体(`New MMD Model`)→ 骨架 + 网格。
- 转换会建 2 个隐藏的备份骨架(`*_backup`),不属于模型,导出时不会带上。

### 路线 B:手动分步(需要干预中间结果时)

面板「手动分步」区**从上到下按编号点**,等价于一键:

```
1 归正骨架位置 → 2 重命名为 MMD → 3 转移 unused 权重① → 4 修正前腕弯曲
→ 5 补全缺失骨骼 → 6 转移 unused 权重② → 7 添加 MMD IK → 8 创建骨骼集合
→ 9 使用 mmd_tools 转换格式        ←— 此线以上在转换前,以下在转换后
→ 10 添加腿部 D 骨 → 11 添加捩骨 → 12 手部权重修正(拇指+掌骨)
→ 13 添加肩P骨 → 14 设置标准付与 → 15 应用付与变换
```

**最小干预变体**(源权重质量好、不想动它,如 alana):面板顶部切到
**「精简·保源权重」**,分步区的 **3、6、11、12** 会自动变灰停用
(不转移 unused 权重、不切捩骨、不改手掌),其余按钮照常从上到下点。
代价是保留一批 unused 骨;好处是源蒙皮原样保留。参考 `test/alana_minimal_flow.py`。
另:步骤 4(修正前腕)只动姿态不动权重,精简路线下仍可用;若 0.5 A-Pose 已拉直肘
则它是冗余的,可跳(alana 脚本即如此)。

#### 何时跳过步 3/6(转移 unused 骨权重)

一句话原理:transfer(见 `convert/weights/transfer.py` 文件头)假设 helper 骨权重是
**待回收的原料**——把它们就近并进标准骨,好让步 11/12 在归一化的权重上重建 MMD 标准
捩骨/掌骨。这个前提不成立时(helper 权重本身就是成品蒙皮),转移只剩两种风险:
有损重蒙皮(扭转/体积梯度被压平进单一最近骨),以及分类器误判(曾把居中的具名布骨
hangings cross / shawl back middle 判成 merge,引发权重湮灭,见
`docs/skirt_physics_design.md` v3)。

| 看什么 | 倾向跳过 | 倾向跑 |
|---|---|---|
| helper 顶点组权重量级 | 总权重几百以上(真承重,如 alana pelvis 1312 顶点/foretwist 736 顶点) | 接近零(纯占位) |
| 是否跑步 11/12 重建捩骨/掌骨 | 不跑(转移没有下游消费者) | 跑(必须先转移) |
| 具名饰骨/布骨密度 | 多且命名怪(误判风险高) | 少且规整 |
| 源蒙皮质量 | 静态摆 pose 已很好 | 源本来就烂,重建损失小 |

跳过的代价(不是免费的):① 源 twist 骨在 MMD 里**无驱动**(VMD 不认、也没配付与,
只跟父骨走),手腕大幅扭转时前臂扭转不沿臂分布——裸臂大动作的模型要重新权衡;
② 残留 unused 骨对 PMXEditor 二次编辑不友好。

权重量级抽查:Blender 里统计可疑顶点组的总权重(或直接跑
`test/alana_minimal_flow.py` 的 verify 段,它会打印 foretwist/pelvis 等组的
顶点数与总权重)。

## 5. (可选)衣服权重转移

贴身衣物(泳衣/紧身衣类)蒙皮很差时用。切到面板第二个 tab:

1. 先选中衣服网格(可多选),**最后加选身体网格**(让身体是活动对象);
2. 点 **「衣服权重转移(身体→衣服)」**。

## 6. (可选)布物理 + 身体碰撞刚体

模型带裙/外套/披风/纱巾/飘带时做这步(头发见 §6.6)。仍在第二个 tab,**顺序固定**:

1. 点 **「1. 身体碰撞刚体(自动)」** —— 给 頭/首/上半身系/下半身/腿/腕 建 kinematic 胶囊,
   半径按网格顶点实测。
2. 点 **「2. 布物理: 裙/外套/披风(自动)」** —— 词表识别布骨,逐骨建刚体+关节,
   锚定到就近标准骨(祖先已有刚体时接它,如挂在发链上的飘带)。布关节按板面对齐朝向(MMD 稳定性关键)。

注意:
- **先 1 后 2**,否则布料没有身体可撞。
- 两个算子可重复运行(已有刚体的骨会跳过)。
- **建完物理后不要点 mmd_tools 的 Build 再导出**——Build 会把布骨绑上动力学刚体,
  场景一求值绑定位就被污染,导出的 PMX 关节出生即违约 → 在 MMD 里全场爆炸。
  想在 Blender 里预览物理:先导出,再在**另一个干净场景**导入该 PMX 后 Build。

## 6.5 (可选)胸部物理

第二个 tab 的「胸部物理」区,四个按钮:

| 按钮 | 作用 |
|---|---|
| **胸部物理(自动)** | 下面 1 + 2 一次做完 |
| **1. 胸骨 + 权重** | 模型已有带权重的胸骨(XPS `boob` / MMD `左胸` / `breast` / `bust` / `oppai` 等)→ 直接复用,不动权重;没有 → 按网格乳尖新建 `左胸`/`右胸`,从胸部骨按距离分出权重(顶点总权重守恒) |
| **2. 胸部刚体 + 关节** | 每侧一个球刚体 + 接父骨刚体的关节(父骨还没刚体会自动补身体刚体) |
| **清除胸部物理** | 删本工具建的刚体/关节;本工具新建的胸骨连同权重并回父骨后删除(复用的胸骨不动) |

参数抄参考 PMX 实测(Purifier Inase 18 等 11 个同系列模型同一约定,按身高 H 归一):
球 r=0.029H、球心在骨头前 0.024H、mass 1、阻尼 0.5/0.5、碰撞组 16(0 起算 15)、不与任何组碰撞;
关节全轴 ±10°、线锁、零弹簧。静止时胸会在 ±10° 限位内自然下垂一点,与参考模型一致。

注意:
- 在「身体碰撞刚体」之前或之后点都可以;
- 同布物理,**导出前不要点 mmd_tools 的 Build**;
- 新建胸骨时乳尖按网格找,挂在布/发/饰物骨上的顶点(蝴蝶结、腰带)会被排除;
  想先确认位置,就先点 1 看 `左胸`/`右胸` 骨头尾是否落在乳房正后方/乳尖,再点 2。

## 6.6 (可选)头发物理

第二个 tab 的「头发物理」区。**只复用模型已有的发骨链**(不造骨、不动权重),没有发骨的模型做不了:

| 按钮 | 作用 |
|---|---|
| **头发物理(自动识别发骨)** | `頭` 之下、名字像头发的骨(`hair` / `髪` / `ponytail` / `braid` / `bangs` / `もみあげ` 等)自动成链 |
| **头发物理(只用选中骨)** | 骨名不规范时用:姿态模式选中发骨(选链首即可,后代自动带上)再点,名字不限 |
| **清除头发物理** | 删本工具建的刚体/关节(骨骼、权重、作锚的身体刚体都不动) |

自动识别的规则:
- **排除**:脸部骨(UE 的 `FACIAL_*_Hair` 是发际线控制点)、眉/睫毛/胡子,发饰(pin/clip/band/acc 等),
  以及布词表命中的骨(发带飘带归布物理)。
- **分叉的发根跟头走**:子树有分叉的骨(发根、帽盖,如 Fiona 的 `hair_root` 系)不建刚体,
  只有从分叉往下的**单条链**进物理;链首尾不带权重的骨(组织用根骨、链尾端点)也不建。
- **锚**:链首接 `頭` 的刚体(没有就自动补,与「身体碰撞刚体」同款)。

参数抄参考 PMX 实测(Purifier Inase 18 等 11 个同系列模型同一约定):每节一个胶囊,沿骨,
半径 0.2×段长(最小 0.006H)、长 = 段长;mass 1、阻尼 0.9/0.99、摩擦 0;碰撞组 10(0 起算 9),
撞身体、不撞布/发/胸;关节恒等朝向、全轴 ±10°、线锁、零弹簧。**每条链的首节(贴头皮)和出生时就
贴着身体刚体的节不撞身体**:前者头后仰时会被颈背顶住、和关节限位打架,后者一开始就被顶开抖个不停。
所以马尾/后发整条压在颈背上的模型(如 alana、rouffe),头发整体不撞身体,大动作时可能穿肩背。

注意:
- **先点「身体碰撞刚体」**,长发才不会穿过肩背;
- 可重复运行(已有刚体的骨跳过);同布物理,**导出前不要点 mmd_tools 的 Build**;
- UE 发链常是很多 1~2cm 的碎节(Fiona 46 条链 254 节),MMD 里物理刚体偏多但能跑;
  手感仍以 MMD 实测为准。

## 7. 导出 PMX

1. 物体模式下单击模型里**任意一个对象**(骨架即可),让它既是选中又是活动对象——导出器会自己
   找到 root,把骨架/全部网格/刚体/关节一起导出(导出菜单项是灰的 = 活动对象不在模型里)。
2. (可选)改模型名:属性编辑器 → 物体属性 → **MMD Model Information** → `Name` / `Name(English)`,
   否则 MMD 里显示为 `New MMD Model`。
3. `文件 → 导出 → MikuMikuDance Model (.pmx)`,右侧选项(看不到点齿轮图标):
   - **Scale = 12.5**(本机 mmd_tools 1.0.2 默认是 1.0,不改的话模型只有十几厘米);
   - 勾 **Copy textures**(贴图复制到 PMX 旁的 `textures\`,所以要存到**单独的空文件夹**);
   - 其余默认。
4. 底部状态栏出现 `Exported MMD model ... to ...`、文件几 MB 即正常;出错只在状态栏报红字。
5. 测试时摆过的姿势不用清:没 Build 的模型导出时自动用静止姿态。**点过 Build 的先点 Clean**。

> 转换出的模型是「米」尺度,×12.5 后即 MMD 常规身高尺度。
> 在 Blender 里给它导 VMD 测试时,VMD 的 scale 要和模型导入 scale 一致
> (如 PMX 以 0.08 导回,VMD 也用 0.08;详见 `docs/TESTING.md`)。

## 8. 验证清单

Blender 侧(能验的):

| 检查项 | 方法 | 通过标准 |
|---|---|---|
| 权重孔洞 | 脚本统计各网格顶点对骨骼组的权重和(见 alana_minimal_flow.py 的 verify 段) | 0 个顶点 < 0.05 |
| 物理结构 | 干净场景导入导出的 PMX → mmd_tools Build → 跑 60 帧静置 | 动态刚体位移 < 0.17m,无飞散 |
| 舞蹈结构 | 同上场景导 VMD 跑全曲 | 布刚体到下半身距离 < 3m(不爆炸) |

MMD 侧(必须实测的——Blender 的新版 Bullet 测不出老版 Bullet 的失稳):

1. 物理演算设为**「常に演算」**(默认"再生時のみ"会首帧跳变,看起来像爆炸);
2. 加载 PMX + 舞蹈 VMD,看:是否爆炸 / 布是否自然摆动 / 是否穿身;
3. 布的**动态手感只认 MMD 实测**,Blender 里的横飘是模拟失真,不是数据问题。
4. 结构逐项看:转头时头发/脸/眼一起动;扭腰胯部不撕裂;脚掌跟随脚尖 IK;手腕/手指弯曲;
   胸部、头发(若加了)晃动幅度,头发是否穿脸/穿肩。

### 已知限制(2026-09 实测,Fiona 等 UE 骨架较明显)

- **手腕小指侧拉尖**:源模型的小指骨权重一直延伸到手腕,小指大幅弯曲时手腕外侧被拉;
  步 12 的手部修正目前只处理**拇指**渗出。
- **抬臂时肩窝褶皱**:UE 的肌肉修正骨(`*_deltoids` / `*_Shoulder01` 等)在游戏里靠驱动器带动,
  MMD 没有驱动器,它们只死跟上臂。
- **没有 `両目` 骨**:动作里的 両目(双眼)关键帧不起作用;不生成表情 morph。
- `センター` 摆在约 0.25×身高(参考模型约 0.43),只影响绕水平轴转 センター 的少数动作。

## 常见问题速查

| 症状 | 原因 → 处置 |
|---|---|
| 一键转换后手指/手臂错位 | 通过脚本/MCP 调用时 override 钉死了 active_object → 只 override window/area/region/screen(见 docs/TESTING.md §2) |
| 跳舞时某块布钉在原地拉成横板 | 权重被转移/湮灭,顶点兜底绑了全ての親 → 具名布/发骨要保留权重(transfer 已内置此规则) |
| MMD 里布料爆炸 | 关节朝向/欧拉序问题(已修,见 skirt_physics_design.md v4);仍爆则查 MMD「常に演算」设置、分叉枝端关节 |
